# Архитектура HR-агента

Один экземпляр на компанию Impact Admissions. Веб-интерфейс для HR, Telegram-бот для сотрудников, фоновый воркер для отложенных действий. Отдел продаж получает дополнительную анкету. Поздравления, сборы и объявления остаются общими для компании.

## Состав

- `hr-ai-agent/backend` — FastAPI, SQLAlchemy 2, Alembic, aiogram 3.
- `hr-ai-agent/frontend` — Next.js, TypeScript, Tailwind. Язык интерфейса русский. Словари `kk` и `en` пустые и подставляют русский текст.
- PostgreSQL 16. Отдельного Redis нет. Планировщик — процесс `app.worker`, он забирает строки `scheduled_actions` через `FOR UPDATE SKIP LOCKED`.
- Отправка в Telegram и вызов модели спрятаны за портами. Без ключей работают тестовые адаптеры и сеть не вызывается.

## Организация

Одна строка организации. При первом создании в неё записываются несекретные значения: название Impact Admissions, часовой пояс Asia/Almaty, username бота `magripaharip_bot`, username суперадмина `Kapanov_30`.

Корпоративный чат для поздравлений: id `-1002615527142`, название «Контент impact», тип `supergroup`. Ссылка-приглашение в приложение и в эти документы не копируется. Пустое значение `CORPORATE_CHAT_ID` уже записанный id не стирает.

База Notion для анкеты отдела продаж: id `40159421a41f80c1bfd5ce5b06de3213`, название Document Hub, тип `database`. Это настройка организации, не секрет. Ссылку на базу в репозиторий не кладём. Ключ интеграции читается только из `NOTION_API_KEY`. Пока ключа нет, страница в Notion не создаётся.

Имя модели и провайдер тоже лежат в организации. Стартовые значения: провайдер `openai`, имя `gpt-4o-mini`. Ключ живой модели читается только из `OPENAI_API_KEY`. Имя модели секретом не является.

Реквизиты сбора на подарок тоже одна настройка организации: перевод Kaspi по телефону и фиксированная сумма. Имя получателя не хранится. HR не вводит реквизиты и сумму в каждом сборе. Участник видит телефон и фиксированную сумму в приглашении.

Файлы обучения отдела продаж — список `{name, url}` в настройках организации. Список изначально пуст. Тексты обучения в код не зашиты.

## Роли и доступ

Веб-роли: `super_admin` и `hr_admin`. Сотрудник в веб не входит, он пользуется ботом. JWT выпускается после входа. Первый суперадмин создаётся только при `APP_ENV=local`, если заданы `BOOTSTRAP_ADMIN_EMAIL` и `BOOTSTRAP_ADMIN_PASSWORD` и в базе ещё нет пользователей. Это локальная инициализация, не запасной вход для продакшена. Пустой `JWT_SECRET` допустим только при `APP_ENV=local`.

Секреты: `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `NOTION_API_KEY`. Они читаются из окружения и в файлы не записываются.

## Сотрудники

Создание и импорт CSV/XLSX ищут дубли по нормализованному ФИО и дате рождения, по Telegram id и по username. Ручной дубль возвращает 409. Приглашение сотрудника — ссылка `https://t.me/{username}?start={invite_token}` на бота, не ссылка в группу. Пока человек не нажал Start или заблокировал бота, HR это видит, а доставка ему не засчитывается.

## Поздравления

Публичное поздравление уходит только в корпоративный чат, только при согласии сотрудника, непустом тексте и подтверждении HR. Скан дней рождения идемпотентен. За семь дней HR получает запись-напоминание. В день события создаётся отправка на час организации. Отмена снимает ещё не выполненное действие. Перед вызовом Telegram статус становится `sending` и фиксируется. Повторный прогон не отправляет статусы `sending`, `sent`, `simulated`, `cancelled`, `skipped`. `failed` сам не повторяется. `simulated` не считается доставкой в Telegram. Если процесс умер после `sending` и до ответа Telegram, строка остаётся `sending`.

## Сборы

Сбор добровольный. Именинник не приглашается, даже если его явно указали. Не участвуют люди с выключенным участием. Отказ в конкретном сборе — статус `declined`. Коллеги не видят чужие отказы и суммы. HR видит. Деньги не считаются полученными, пока HR не подтвердит перевод. Открытие и рассылка приглашений идемпотентны.

## Объявления

Сегмент: все, подразделения или конкретные люди. Можно запланировать или отправить сразу. RSVP «буду» / «не смогу» доступен только если сообщение доставлено и RSVP включён. В счётчике доставленных учитывается только статус `sent`. Типы `survey` и `reminder` — подписи без отдельных продуктов.

## Ассистент

Задачи: поздравление, объявление, сбор, идеи подарка, свободная команда. В модель уходит только разрешённый набор полей. Тестовый адаптер возвращает список полученных полей и ничего не отправляет по сети. Утверждение черновика создаёт поздравление в `pending_approval` и сбор в `draft`. Оно не открывает сбор и не шлёт рассылку. Если `OPENAI_API_KEY` пуст или провайдер организации не `openai`, остаётся тестовый адаптер.

## Онбординг отдела продаж

После `/start` без приглашения бот предлагает две кнопки. «Я уже в команде» не создаёт анкету и не пишет в Notion: нужна персональная ссылка HR. «Я новый в отделе продаж» задаёт вопросы по одному: ФИО, обращение, телефон, дата рождения, должность, дата выхода, город, затем отдельный вопрос о согласии на публичное поздравление. Согласие по умолчанию не включается. Подразделение — «Отдел продаж», статус после анкеты — активный. Повтор того же Telegram id вторую карточку не создаёт.

Своя база сотрудников заполняется всегда. В Notion ушли бы только поля анкеты плюс Telegram id, username и время заполнения. Кадровые поля вроде согласия и приглашения в этот набор не входят. Без `NOTION_API_KEY` запись помечается `skipped`, причина пишется в журнал, страница не создаётся. Живой вызов Notion с этой машины не выполняется. Если пакет файлов пуст, бот говорит, что материалы ещё не загружены.

## Журнал и резервная копия

Изменения настроек, сотрудников и подтверждения оплат пишутся в `audit_log`. Ошибки приложения — структурированный JSON в stdout. Скрипт `hr-ai-agent/scripts/backup_db.sh` делает `pg_dump` из `DATABASE_URL`.

## Чего нет

Опросы как продукт, процесс адаптации всех отделов, годовщины работы, повторяющиеся напоминания и аналитика не сделаны. Платёжного провайдера нет: подтверждение перевода HR — точка расширения.
